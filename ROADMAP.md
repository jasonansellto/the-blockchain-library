# Roadmap

## The Blockchain Library

This roadmap describes strategic direction rather than a binding delivery schedule. Priorities may change as the knowledge graph, contributor community, and technical requirements evolve.

## Completed foundation

### v1.0 — Knowledge Platform Foundation

- Structured Knowledge Engine
- Canonical object model
- Knowledge graph
- Validation
- Static public exports
- JSON-LD groundwork
- Mintlify integration

### v1.1 — Knowledge Expansion

- 100 canonical topic objects
- 250 structured glossary entries
- generated topic and glossary pages
- broader graph coverage

### v1.2 — Dynamic Knowledge

- curated human navigation
- unified structured catalog
- related-resource index
- search index
- native knowledge catalogs
- route cleanup for Mintlify

### v1.3 — Resource Enrichment

- enriched books
- enriched research
- coverage model
- canonical resource pages

### v1.4 — Learning & Developer Enrichment

- 10 tutorials
- 10 code examples
- 10 AI prompt patterns
- 10 quizzes
- native resource catalogs

### v1.5 — Repository Professionalization

- vision and architecture documentation
- formal data model
- editorial standards
- contributor governance
- security policy
- code of conduct
- changelog and project status
- GitHub contribution templates

## Current focus

The current priority is quality and coverage rather than further repository restructuring.

Near-term work should:

- enrich the weakest high-value topics;
- expand glossary depth;
- improve tutorial and code-example coverage;
- grow research connections;
- strengthen citations;
- improve knowledge-object review states;
- refine related-resource generation.

## v2.0 — Knowledge API

Primary goal: expose the structured knowledge model through a production, versioned, read-only API.

Planned capabilities:

- topic lookup;
- glossary lookup;
- catalog search;
- related-resource lookup;
- graph traversal;
- book and research lookup;
- coverage data;
- stable response contracts;
- API documentation and examples.

A production API should preserve canonical IDs and avoid creating a second content model.

## v2.x — Interactive Knowledge Products

Potential capabilities:

- interactive graph explorer;
- advanced structured search;
- contributor dashboard;
- coverage analytics;
- learning progress;
- interactive assessments;
- saved learning paths.

These products should consume the same Knowledge Engine data.

## v2.5 — Learning Platform

Potential capabilities:

- accounts and progress tracking;
- personalized learning paths;
- competency checks;
- adaptive quizzes;
- study plans;
- completion records;
- optional certifications.

Learning features should remain educational rather than gamified for engagement alone.

## v3.0 — AI-Native Knowledge Platform

Potential capabilities:

- AI tutor grounded in canonical objects;
- citation-aware answers;
- developer mode;
- research mode;
- prerequisite-aware explanations;
- automatic knowledge-gap detection;
- multilingual retrieval;
- evaluation against canonical references.

AI should operate as an interface to the Knowledge Engine, not a substitute for editorial review.

## Community roadmap

As contribution volume grows, the project may add:

- formal maintainer roles;
- reviewer groups by subject;
- structured proposal process;
- translation working groups;
- research review workflow;
- community discussions;
- periodic content audits.

## Long-term targets

These are directional targets, not promises:

- 500+ canonical topics;
- 1,000+ glossary entries;
- 100+ tutorials;
- 100+ code examples;
- 100+ quizzes;
- 100+ AI prompt patterns;
- 25+ learning paths;
- deeper research coverage;
- broader publication metadata.

Quality should take precedence over numerical targets.

## Risks

Key risks include:

- stale technical information;
- duplicate or contradictory definitions;
- over-generation of low-value pages;
- weak citation quality;
- promotional bias;
- broken relationships;
- presentation-layer coupling;
- contributor inconsistency.

The architecture and governance documents are intended to reduce these risks.

## Success criteria

The roadmap is working when:

- knowledge objects remain consistent as volume grows;
- contributors can identify meaningful gaps;
- humans can navigate without sidebar overload;
- AI and search can reuse structured data directly;
- release changes remain auditable;
- the project can add new interfaces without rebuilding its knowledge model.
