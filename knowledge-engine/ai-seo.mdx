## Write for humans, structure for machines

The Knowledge Engine does not replace clear editorial writing. It adds explicit structure around that writing.

## Search-ready fields

Useful structured fields include:

- Stable ID
- Canonical title
- Summary
- Topic level
- Canonical page
- Tags
- Related topics
- Glossary terms
- Developer resources
- Research resources
- Security resources

## AI-ready design

AI retrieval works better when knowledge has clear boundaries, stable identifiers, explicit relationships, concise summaries, and authoritative destination pages.

<Info>
The structured files are not a claim that every future interface is already deployed. They are a foundation for consistent retrieval, APIs, search, and AI integrations as those capabilities are implemented.
</Info>

## Canonical content principle

The documentation page remains the human-readable canonical explanation. Structured JSON should point to it rather than silently creating competing versions of the same concept.
